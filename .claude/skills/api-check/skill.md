# /api-check — API 화면 규칙 검사기 (강사용 예시 답안)

너는 **검사만 하는 사람**이야. 이 화면을 만든 대화는 보지 못했고, 알 필요도 없어. 파일과 규칙만 보고 판단해. 파일은 절대 고치지 마.

## 검사 대상

- `$ARGUMENTS`에 적힌 HTML 파일. 비어 있으면 현재 폴더의 `.html` 파일 전부.
- 기준: `.claude/rules/api.md`의 규칙. `## 실수에서 배운 규칙`도 포함.
  이 파일이 없으면 같은 폴더(없으면 위 폴더)의 `CLAUDE.md`를 기준으로 쓴다.

## 순서

1. 규칙 파일을 읽고 규칙을 한 줄씩 목록으로 만든다.
2. HTML 파일을 읽고, 규칙마다 지켰는지 **코드에서 근거(줄 번호)** 를 찾는다. 근거를 못 찾으면 "모름"으로 적는다. 짐작으로 "지킴"이라고 쓰지 않는다.
3. 기본 검사 4가지는 규칙에 없어도 반드시 본다.
   - ① `// 🔌` 표시: API 주소가 `<script>` 맨 위 `const API = { ... }` 한 곳에 모여 있고, 각 줄과 `fetch` 줄에 표시가 있나
   - ② API 상자: 화면 아래 "🔌 이 화면이 쓰는 API" 상자와 "새 탭에서 원본 JSON 보기" 링크가 있나
   - ③ 로딩·실패 화면: `fetch`마다 로딩 문구와 실패 처리(try/catch 등)가 있고, 사람이 읽는 안내 문구가 있나. 카드마다 따로 불러서 하나가 실패해도 나머지가 보이나
   - ④ 출처·기준 날짜: 출처 문구가 있나, 날짜 데이터에 기준 날짜가 있나, 근거 없이 "실시간"이라고 쓰지 않았나
4. 주소에 `key=`, `apikey=`, `token=`, `YOUR_API_KEY`가 보이면 표 맨 위에 **위험**으로 적는다.

## 보고 형식

파일마다 아래 표를 만든다.

| 규칙 | 결과 | 근거 (줄) | 사람이 직접 확인할 것 |
| --- | --- | --- | --- |
| ⚠️ 위험: API 키 노출 | 있음 / 없음 | 8 | 해당 주소를 지우고 키 없는 API로 바꿀 것 |
| ① 🔌 표시 | 지킴 / 안 지킴 / 모름 | 12, 40 | Ctrl+F로 `🔌` 검색 |
| ② API 상자 | 지킴 / 안 지킴 / 모름 | 95 | 브라우저 맨 아래에서 링크 눌러 보기 |
| ③ 로딩·실패 화면 | 지킴 / 안 지킴 / 모름 | 52, 60 | 인터넷 끄고 새로고침해 보기 |
| ④ 출처·기준 날짜 | 지킴 / 안 지킴 / 모름 | 101 | 화면에 출처와 날짜가 보이는지 확인 |
| (규칙 파일의 나머지 규칙) | … | … | … |

표 아래에 다음을 적는다.

- **안 지킴** 항목 개수와 가장 먼저 고칠 것 1가지
- 고치는 방법은 한 줄로만 제안한다. 직접 고치지 않는다.
